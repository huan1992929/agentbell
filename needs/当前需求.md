# 当前需求

## 已确认的选择（2026-09-25，用户答复）

- 提醒方式：**系统通知 + 自定义声音**，以及**菜单栏常驻状态**（用户多选了这两项）
- 手机推送、终端响铃：本轮不做
- Vibe Island 残留：**清理掉**（已授权）

## 阶段划分

### 阶段 0 · 验证前提（当前）

两个地基事实必须先坐实，否则后面的实现方向可能整个错：

1. **Claude 桌面端是否真的会触发 `~/.claude/settings.json` 里的 hooks。** 终端 CLI 肯定会触发，桌面端待证。
2. **Codex `notify` 实际传入的参数长什么样**（字段名、是否含会话标识、turn 是否区分完成与等待输入）。

做法：挂一个只写日志、不做任何提醒的探针，用户正常使用几分钟后读日志。

完成条件：`probe/probe.log` 中能分别看到来自 Claude 桌面端和 Codex 的事件记录，且能判断出哪个字段代表"任务完成"。

若 Claude 桌面端 hooks 不触发，退路是轮询 `~/.claude/projects/` 下的会话 JSONL 判断结束——能做但更脏，优先走 hooks。

### 阶段 1 · 最小可用版

- 清理 Vibe Island 残留（改 `~/.claude/settings.json` 前先备份）
- 正式事件脚本 + 系统通知 + 两种提示音（Codex 与 Claude 用不同音色）
- 交付后提醒功能即生效，菜单栏是后续增强

完成条件：Codex 跑完一个任务、Claude 桌面端跑完一轮，各自弹出通知并发声。

### 阶段 2 · 菜单栏常驻

- Swift 原生菜单栏 App（`LSUIElement`，不占 Dock）
- 显示哪个 agent 在跑、跑了多久、刚完成几个
- LaunchAgent 开机自启

完成条件：菜单栏图标常驻，点开能看到各 agent 状态；重启后自动运行。

## 已识别风险

1. **Claude 桌面端 hooks 可能不触发** → 阶段 0 定论，退路见上。
2. **未签名 App 发通知可能被 macOS 拦。** 对策：ad-hoc 签名（`codesign -s -`）；再不行退回 `osascript`，需用户一次性授权。
3. **Codex 串联必须零影响。** 透传全部参数、stdin/stdout 和退出码，Codex Computer Use 原有行为不能变。
