# AgentBell 设计说明

## 一、要解决的问题

Codex CLI 跑完任务没有任何提醒；Claude 桌面端虽有系统横幅，但和 Codex 各管各的，没有统一的、可区分的提示。本项目提供一个纯本地的统一提醒层。

## 二、核心约束

1. **事件脚本必须毫秒级返回。** hooks 和 notify 都在 agent 的关键路径上，任何阻塞都会拖慢 agent 本身。脚本内不做网络请求、不等待子进程、结尾必须 `exit 0`。
2. **绝不破坏 Codex Computer Use。** `~/.codex/config.toml` 的 `notify` 已被它占用，只能串联，必须原样转发参数并保留其行为。
3. **不挂 PreToolUse / PostToolUse。** 那会在每次工具调用时起一个进程。Vibe Island 就是这么干的，是本项目要清理的对象。
4. **不装任何第三方依赖。** 只用系统自带的 `sh`、`python3`、`osascript`、`afplay`。不用 Homebrew 装 terminal-notifier。

## 三、架构

```
Codex turn-ended ──→ agentbell-codex-notify ──┬──→ 原 Computer Use（后台透传）
                                              └──┐
Claude 桌面端 hooks ──→ agentbell-event ─────────┤
  Stop / Notification / PermissionRequest       ↓
                                        记录 events.jsonl
                                        afplay 提示音
                                        osascript 通知
```

阶段 2 引入菜单栏常驻进程后，通知与声音改由它统一发出（通知权限只需授权一次，图标归属清晰），事件脚本退化为纯上报。**阶段 1 先用脚本直接发，保证短路径可用。**

## 四、运行时目录

源码仓库在 `~/Desktop/code/agentbell`，安装后运行时目录在 `~/.agentbell/`：

```
~/.agentbell/
  bin/agentbell-event           # 统一事件入口（Claude hooks 调用）
  bin/agentbell-codex-notify    # Codex 串联包装
  config.json                   # 声音映射、开关、原 notify 程序路径
  logs/events.jsonl             # 原始事件日志，排查与后续解析都靠它
  backups/<时间戳>/             # 安装前的配置备份
```

## 五、事件脚本行为

`agentbell-event <来源>`：

1. 读 stdin（Claude hooks 以 JSON 从 stdin 传入；读取要带超时，避免没有 stdin 时卡住）
2. 追加一行 JSON 到 `logs/events.jsonl`：时间戳、来源、argv、原始负载
3. 按 `hook_event_name` 判定是否提醒：
   - `Stop` → 任务完成，提醒
   - `Notification` / `PermissionRequest` → 需要处理，提醒（用不同音）
   - 其他 → 只记录不提醒
4. `afplay` 放对应提示音（后台起，不等待）
5. `osascript` 发通知（失败也不影响退出码）
6. `exit 0`

**日志永远写。** 即使判定不提醒也写——这既是阶段 0 的探针，也是后续调参和排障的唯一依据。

### 默认音色

| 事件 | 声音 |
|---|---|
| Codex 任务完成 | `/System/Library/Sounds/Submarine.aiff` |
| Claude 任务完成 | `/System/Library/Sounds/Glass.aiff` |
| 需要批准 / 提问 | `/System/Library/Sounds/Ping.aiff` |

写进 `config.json`，用户可改。

## 六、配置改动

### Claude 桌面端 `~/.claude/settings.json`

只挂三个事件，命令统一为：

```
/bin/sh -c '"$HOME/.agentbell/bin/agentbell-event" claude >/dev/null 2>&1; exit 0'
```

同时**移除全部 vibe-island 残留**：11 个 hooks 和被它接管的 `statusLine`（已获用户授权）。

用 `python3` 的 `json` 模块读改写，保留文件里其他键不动。

### Codex `~/.codex/config.toml`

把 `notify` 指向串联脚本，固定参数保持 `"turn-ended"` 不变：

```toml
notify = ["<HOME>/.agentbell/bin/agentbell-codex-notify", "turn-ended"]
```

原程序路径存进 `config.json`，串联脚本据此转发。

**TOML 的修改方式**：`python3` 的 `tomllib` 只能读不能写，机器上也没有 `tomli-w`。**只做单行文本替换**，定位以 `notify` 开头（允许前导空白）且在顶层表内的那一行，整行替换。不要重写整个 TOML 文件——那会丢掉注释和格式，而这个文件里还有用户的项目信任配置。

## 七、安装与卸载

`install.sh`：
1. 把 `~/.claude/settings.json` 和 `~/.codex/config.toml` 复制到 `~/.agentbell/backups/<时间戳>/`
2. 复制脚本到 `~/.agentbell/bin/`，`chmod +x`
3. 写 `config.json`（含探测到的原 notify 程序路径）
4. 改两份配置
5. 打印改了什么、备份在哪

`uninstall.sh`：从最近一次备份还原两份配置，保留日志目录。

**回退必须可用**，这是硬要求：改的是用户每天在用的两个 agent 的配置。

## 八、不做的事

- 不写单元测试框架、不建 CI、不做全量回归
- 不做手机推送、终端响铃（本轮用户没选）
- 不碰菜单栏（阶段 2）
- 不为验证去装浏览器或额外工具

## 九、完成条件

1. 公开仓库已建并推送
2. 跑完 `install.sh` 后：Codex 完成一次任务有声音；Claude 桌面端完成一轮有声音
3. Codex Computer Use 原有行为不变
4. `logs/events.jsonl` 里能看到两边的原始负载
5. `uninstall.sh` 能完整还原两份配置

第 2、3 条里 Claude 桌面端那部分**需要人工确认**——桌面端是否真的触发 hooks 尚未证实，这是本项目最大的未知。若日志里始终没有 claude 来源的记录，说明桌面端不走 `settings.json` 的 hooks，退路是轮询 `~/.claude/projects/` 下的会话 JSONL 判断结束。
