# 任务：AgentBell 阶段 2 — 菜单栏常驻

**目标**：菜单栏常驻一个图标，一眼能看到 Claude 正在跑什么、跑了多久，以及两边最近完成了哪些任务。开机自动启动。

**范围**

1. Swift 原生菜单栏 App（`LSUIElement = true`，不占 Dock），用 `swiftc` 编译并手工组 `.app` bundle，`codesign -s -` 做 ad-hoc 签名。机器上只有 Command Line Tools，**没有完整 Xcode，不要生成 Xcode 工程**。
2. 状态来源：监听 `~/.agentbell/logs/events.jsonl` 的新增行。用轮询文件大小变化即可（1 秒一次），不要引入第三方库。
3. Claude 侧增挂 `UserPromptSubmit` hook 获得"开始"信号，与既有 `Stop` 配对算出运行中状态和已运行时长。**仍然不挂 PreToolUse / PostToolUse**。`install.sh` / `uninstall.sh` 要同步更新。
4. 菜单内容：当前运行中的 Claude 会话（项目目录名 + 已运行时长）、最近完成的若干条（来源、项目、完成时刻、最后一句回复的摘要）、一个退出项。
5. LaunchAgent 开机自启：`~/Library/LaunchAgents/` 下的 plist，`RunAtLoad`。装卸由 `install.sh` / `uninstall.sh` 负责。

**必要约束**

- **不要动通知与提示音的发送方式**。见 `needs/decisions.md` 的 D001：通知继续由事件脚本发出，App 只做状态显示。阶段 1 已验证可用的东西不要改。
- **不要围绕"等待批准"做界面**。见 D002：用户始终以完全访问模式运行，`PermissionRequest` 实际不触发。
- **Codex 没有"开始"信号**。见 D003：Codex 只显示"最近完成"，不要为了做运行中状态去轮询进程列表或解析终端。
- 不装任何第三方依赖，不引 SPM 包。
- 改用户配置前照旧备份到 `~/.agentbell/backups/<时间戳>/`。
- 仓库是公开的：不要把绝对家目录路径、token 或无关个人信息写进去。

**完成条件**

1. 菜单栏图标常驻，点开能看到运行中与最近完成的条目。
2. 新开一个 Claude 桌面端会话跑一轮，菜单栏能反映出"运行中 → 完成"的变化。
3. Codex 跑完一次任务，菜单栏"最近完成"里出现对应条目。
4. 退出登录或重启后 App 自动启动（能验证就验证，不能就说明如何验证）。
5. `uninstall.sh` 能完整卸掉 App、LaunchAgent 和新增的 hook，并还原配置。**实际执行一次验证，再重新安装**。
6. 阶段 1 的提醒功能不受影响：跑一次 Codex 任务确认仍然有声音。

**不要做**：单元测试框架、CI、全量回归、手机推送、把通知迁进 App。

**参考**：`needs/decisions.md`（三条已确认决定，优先级高于旧文档）、`needs/设计说明.md`、`needs/progress.md`（阶段 1 的真实验证记录与生产状态）。

**交付时按此结构回复**：已完成 / 使用入口 / 基础检查 / 人工确认 / 已知问题。
